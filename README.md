# LogAnalyzer

C# / WinForms / .NET Framework 4.8 기반 Windows 프로그램입니다. 최신 1번 시안의 흰색 작업 영역, 옅은 회색 사이드바, 파란색 주요 버튼과 둥근 버튼 모서리를 적용했습니다. 다크 모드와 기존 타이밍 차트·프리셋·문자열 강조·분리 창 기능을 함께 지원합니다.

## 실행

- 설치: `dist\LogAnalyzer-Setup.exe`를 실행합니다. Windows 10/11 64비트와 .NET Framework 4.8 이상이 필요합니다. 시작 메뉴 및 선택한 경우 바탕화면에 바로가기를 만듭니다.
- 설치 없이 실행: `bin\Release\LogAnalyzer.exe`를 실행합니다. 이 폴더에는 기존 사용자 설정과 최신 프리셋을 보존했습니다.
- 다른 PC 배포: `dist\LogAnalyzer-Portable.zip` 또는 Setup을 사용합니다. 개인 로그 경로와 프리셋은 배포 파일에 포함하지 않습니다.

설치 기본 위치는 `%LOCALAPPDATA%\Programs\LogAnalyzer`이며 관리자 권한이 필요하지 않습니다. `settings.ini`, `timing-keywords.ini`, `timing-presets`는 실행 파일 옆에 저장합니다. 기존 프리셋을 설치본에서도 사용하려면 프로그램을 닫고 `bin\Release`의 이 파일·폴더를 설치 폴더로 복사합니다. 재설치/업데이트 시 사용자 설정은 유지하며, 제거해도 사용자 설정은 남겨 둡니다.

앱 아이콘 원본과 Windows ICO는 `assets`에, 설치 스크립트는 `installer`에 있습니다.

1. **찾아보기**를 누르면 Windows 탐색기형 폴더 선택 창이 열립니다. 주소 표시줄을 클릭하거나 **Alt+D**를 누른 뒤 로그 폴더 경로를 붙여넣고 **Enter**로 이동합니다. **폴더 선택**을 누르면 로그를 불러옵니다. 메인 화면의 경로 입력란과 **불러오기** 버튼도 사용할 수 있습니다. 하위 폴더도 탐색합니다.
2. 왼쪽의 프로세스나 파일 이름을 선택하면 개별 조회합니다. **전체 보기**로 통합 조회로 돌아갑니다. 체크된 파일과 상단 종류 필터가 검색·차트에도 공통 적용됩니다.
3. 기본은 Task별 색상이 없는 컬럼 뷰입니다. **프로세스 구분**을 누르면 통합 로그·검색 결과·프로세스 목록을 색상으로 구분합니다. 프로세스를 선택하고 **배경색**을 누르면 컬러 팔레트가 열립니다. **다크 모드**는 중립 배경을 어둡게 표시하며, 프로세스 구분이 켜져 있으면 같은 색 계열을 어둡게 조정합니다.
4. 아래 검색창에 문자열을 입력합니다. 입력을 멈추거나 **검색**을 누르면 결과가 아래에 나타납니다. 대소문자 구분·정규식 옵션을 지원합니다. 결과를 더블클릭하면 메인 원문으로 이동합니다.
5. 메인 로그 더블클릭은 전체 원문 상세 보기입니다. 오른쪽 클릭 메뉴에서 원문을 복사할 수 있습니다. 열 너비와 각 뷰어 사이 경계선은 드래그할 수 있습니다.

통합 로그 또는 검색 결과의 행을 한 번 클릭하면 해당 시각으로 차트 수직선이 이동합니다. 확대 구간 밖의 로그를 선택하면 확대 배율을 유지하면서 시간 축을 이동합니다. 시간을 인식하지 못한 행은 차트 위치를 변경하지 않습니다.

각 뷰어의 **새 창**을 누르면 통합 로그와 검색 결과를 각각 별도 창으로 크게 볼 수 있습니다. 분리 창 왼쪽의 **Task / 파일**에서 프로세스나 개별 파일을 선택하고 체크로 조회 대상을 지정할 수 있습니다. **전체 보기**는 전체 Task로 돌아가며 **배경색**은 선택한 프로세스의 색상을 변경합니다. 선택·체크 상태는 메인 창과 다른 분리 창에도 함께 반영되며 필터·검색·차트 연동을 유지합니다. 사이드바와 로그 사이 경계선으로 너비를 조절할 수 있습니다. **원래 위치**, **뷰어 가져오기** 또는 창 닫기로 원래 화면에 복원합니다.

## 창 배치 단축키

메인 창과 통합 로그·검색 결과·타이밍 차트의 분리 창에서 사용할 수 있습니다.

- `Alt + ← / →`는 현재 모니터의 작업 표시줄을 제외한 왼쪽 또는 오른쪽 절반에 창을 배치합니다.
- `Alt + ↑`는 최대화합니다. `Alt + ↓`는 최대화 또는 좌우 배치를 한 단계 되돌립니다. 일반 창에서는 최소화합니다.
- 프리셋이나 로그 종류 선택 상자에서는 `Alt + ↓ / ↑`로 목록을 열고 닫을 수 있습니다. 좁은 창에서는 스크롤로 도구에 접근할 수 있습니다.

## 시간 구간

기본은 전체 시간입니다. 왼쪽 사이드바의 **시간 구간**을 체크하고 **시작 / 끝** 날짜와 시간을 지정하면 통합 로그, 검색 결과, 타이밍 차트 및 분리 창이 같은 구간으로 갱신됩니다. Task·파일·종류·검색 조건과 함께 적용되며 차트 시간 축도 지정한 구간을 사용합니다.

- 초 단위로 설정하며 끝 시간의 해당 초 전체를 포함합니다. 예: 10:50:10 ~ 10:50:13은 10:50:13.999 로그도 포함합니다. 같은 초를 양쪽에 지정하면 해당 1초만 조회합니다.
- 시간 구간이 켜져 있으면 시간을 인식하지 못한 로그는 제외합니다. 날짜가 달라도 시작·끝 순서가 맞으면 조회할 수 있습니다.
- 시작이 끝보다 늦으면 하단에 시간 구간 오류를 표시하고 마지막 유효 결과를 유지합니다.
- **전체 시간** 또는 시간 구간 체크 해제로 시간 필터를 해제합니다. 기존 Task·종류·검색 조건은 유지합니다.
- 재실행 시 기본 전체 시간으로 시작합니다. 시간 필터를 사용하지 않고 폴더를 불러오면 시작·끝 입력값에 해당 로그의 최소·최대 시각을 채웁니다.

## 컬럼 뷰와 문자열 강조

1. 기본 모드는 날짜·시간·프로세스·종류·로그·행 컬럼을 유지합니다. 날짜는 `yyyy-MM-dd`, 시간은 `HH:mm:ss.fff`로 분리하며 검색 결과와 별도 창에도 같은 컬럼을 사용합니다. `로그` 본문에서는 파서가 인식한 날짜·시간 필드를 제외하여 중복 표시하지 않습니다. 일반 모드는 흰색, 다크 모드는 중립 어두운 배경입니다.
2. **프로세스 구분**이 꺼진 상태에서 통합 로그 또는 검색 결과 뷰어의 `로그` 셀에서 원하는 문자열을 드래그한 뒤 우클릭 메뉴의 **선택 문자열 색상**을 선택하면 컬러 팔레트가 열립니다. 통합 로그의 **강조 ▾ → 선택 문자열 색상** 메뉴에서도 색상을 지정할 수 있습니다. 선택은 드래그를 시작한 한 로그 행 안으로 제한되며, 위아래로 움직여도 다른 행의 문자열을 포함하지 않습니다. 선택한 부분만 복사하려면 Ctrl+C를 누릅니다.
3. 컬러 팔레트에서 배경색을 고르면 두 뷰어의 동일한 문자열에 함께 적용됩니다. 대소문자를 구분하는 정확한 문자열 일치 방식입니다.
4. 다른 문자열에도 색을 추가할 수 있습니다. 같은 문자열의 색을 다시 지정하면 교체하고, 강조 영역이 겹치면 나중에 지정한 색을 적용합니다. **강조 지우기**는 모든 강조를 제거합니다.

필터 변경·테마 전환·별도 창 전환 후에도 강조 규칙을 유지합니다. 강조 문자열과 색상을 변경하거나 지우면 **저장 \***로 표시됩니다. 상단 **저장**을 누르면 선택한 프리셋 INI에 키워드와 강조 설정이 함께 저장되며, 프리셋 전환·재실행 시 해당 프리셋의 강조를 복원합니다. 미저장 상태로 전환하거나 종료하면 저장 여부를 확인합니다. **프로세스 구분**을 켜면 프로세스 배경색을 표시하고, 끄면 문자열 강조를 다시 표시합니다. 긴 로그는 컬럼 너비를 늘리거나 별도 창에서 조회할 수 있습니다.

표시용 본문만 바뀌며 원본 파일·원문 복사·상세 보기·원문 검색은 유지합니다. 시간을 인식하지 못한 행은 원문 그대로 표시합니다. 사용자 지정 시간 정규식도 동일하게 적용하며, 인식한 시각 외에 메시지에 포함된 다른 날짜·시간은 제거하지 않습니다.

## 타이밍 차트와 프로그램별 키워드 프리셋

**키워드 순번 연동:** 키워드를 추가하면 앞에 1, 2, 3… 순번이 표시됩니다. `연동할 키워드 순번` 드롭다운에서 이미 등록된 다른 키워드의 순번을 고릅니다. 예를 들어 1번 행에서 2번을 선택하면 **1번 로그 → 2번 로그**를 발생 순서대로 1:1 연결합니다. Task나 로그 종류에 관계없이 현재 통합 로그 안에서 비교하며, A와 B는 각각 등록된 문자열·대소문자 옵션을 사용합니다.

각 행의 **연동 로그 간격 (ms) / 연동 로그 간격 허용 편차 (%)**는 **로그 간격 (ms) / 로그 간격 허용 편차 (%)**와 독립된 설정입니다. `이상 감지` 체크가 꺼져 있어도 연동 순번을 지정하면 연동 검사합니다. `없음`을 선택하면 해당 행의 연동 기준과 허용 편차가 회색으로 표시되고 편집이 잠깁니다. 순번을 다시 선택하면 기존 값으로 편집을 이어갈 수 있습니다. 연동 기준이 0이면 통합 로그의 완성된 양수 간격이 5개 이상일 때 중앙값을 사용합니다. 허용 편차를 벗어난 구간과 양쪽 로그 마크가 빨간색으로 표시되며, 툴팁에 순번·키워드·실제 간격·기준이 나옵니다. 시작 로그가 남고 이후에 허용 범위에 맞는 연결이 있으면, 남는 개수 안에서 연결 순서를 복구합니다. 복구 중 연결되지 못한 로그는 해당 마크만 빨간색으로 표시하며 툴팁은 `연동 대상 없음`으로 표시합니다. 개수가 맞는 연결은 FIFO를 유지하여 실제 연속 지연을 숨기지 않습니다. 자동 기준은 남는 시작 로그가 있을 때 순방향·역방향 FIFO 중앙값 중 작은 값을 사용합니다. 이 복구는 로그 식별자 대신 발생 순서·개수·설정한 시간 범위에 따른 추정입니다.

순번은 키워드 설정, 차트 레인과 키워드 버튼에서 동일합니다. 위/아래 이동 시 기존 연결 대상을 유지하면서 순번을 갱신하고, 대상 키워드를 삭제하면 해당 연결만 해제합니다. 키워드 이름을 바꿔도 연결은 유지됩니다. 대상 키워드 표시를 꺼도 등록된 연결 대상으로 사용할 수 있습니다. 설정은 프리셋에 저장되어 재실행·복사·전환 시 함께 복원됩니다.

같은 로그 한 줄을 자기 자신과 연결하지 않으며, 짝이 없는 시작/종료는 간격 이상으로 추정하지 않습니다. 현재 Task·파일·종류·시간 필터 밖의 이벤트는 연결에 사용하지 않습니다. 이전 버전의 활성 종료 문자열 설정이 있으면 등록된 키워드 순번으로 변환하며, 대상이 없으면 키워드를 추가해 기존 기준·편차를 보존합니다.

**선택 구간 내보내기:** 차트에서 우클릭하여 **시작 지점 지정**, **끝 지점 지정**을 선택한 뒤 **선택 구간 내보내기…**를 누릅니다. 로그 마크 위에서는 해당 로그의 정확한 시각, 빈 공간에서는 시간 축의 위치를 사용합니다. 선택 범위는 파란 음영과 점선으로 표시하며, 양 끝 시각을 포함합니다. 한쪽이 없거나 시작이 끝보다 늦으면 내보내기가 비활성화됩니다. **구간 선택 해제**로 지울 수 있습니다.

내보내기는 현재 Task·파일·종류·시간 필터에 해당하는 **통합 로그 원문**을 시간순 UTF-8 `.log`로 저장하며 검색 결과로 제한하지 않습니다. 표시용 본문 대신 날짜·시간이 남은 원문을 사용합니다. 메인/분리 차트 모두 사용할 수 있고 확대·이동 중에도 선택을 유지합니다. 조회 조건이나 프리셋이 바뀌어 차트 데이터가 갱신되면 선택 구간은 초기화됩니다. 상단 **취소**로 저장 작업을 취소할 수 있으며 완성된 임시 파일만 교체하므로 취소 시 기존 목적지 파일을 유지합니다. 빈 파일을 포함한 불러온 원본 로그에는 덮어쓰지 않습니다.

차트 제목 오른쪽 **새 창**을 누르면 차트·프리셋 목록·키워드 도구가 별도 창으로 이동합니다. 창을 최대화해 더 많은 키워드를 한 번에 볼 수 있으며, 넘치는 행은 오른쪽 세로 스크롤 또는 Shift+휠로 조회합니다. 왼쪽 Task/파일 선택은 메인과 다른 분리 창에 동기화됩니다. 통합 로그·검색 결과의 행 선택과 차트 마크 선택도 연결됩니다. 분리하면 메인 화면의 차트 영역이 접혀 통합 로그와 검색 결과가 커집니다. **원래 위치** 또는 창 닫기로 분리 전 차트 높이를 복원합니다. 그동안 메인 창을 작게 줄였다면 두 로그 뷰어의 최소 공간을 보장하는 높이로 복원합니다.

- **키워드**: 포함 문자열, 사용 여부, 대소문자 구분, 차트 색상을 편집합니다. 추가·삭제·순서 변경이 가능합니다.
- 차트 위 키워드 버튼으로 해당 레인을 켜고 끕니다.
- 상단 프리셋 목록에서 사용할 프로그램의 설정을 선택합니다. 재실행하면 마지막 선택을 복원합니다.
- **프리셋 ▾ → 새 프리셋**: 프로그램 이름을 입력하여 키워드와 문자열 강조가 없는 프리셋을 만듭니다. **현재 설정 복제**는 현재 키워드·색상·간격 검사·문자열 강조를 새 이름으로 저장합니다.
- **프리셋 ▾ → 이름 변경 / 삭제**: 저장된 프리셋을 관리합니다. 같은 이름은 덮어쓰지 않으며 최소 한 개의 프리셋을 유지합니다.
- **저장**: 선택한 프리셋의 INI에 저장합니다. 각 파일은 실행 파일 옆 `timing-presets/프로그램 이름.ini`에 보관합니다.
- **프리셋 ▾ → INI 가져오기 / INI 내보내기**: 기존 키워드 파일을 새 프리셋으로 등록하거나 다른 PC와 공유할 INI를 만듭니다. 가져오기 실패 시 기존 설정을 유지합니다.
- 미저장 변경은 `저장 *`로 표시합니다. 프리셋을 전환하거나 종료할 때 저장 여부를 확인합니다.
- 최초 실행 시 관리 폴더에 프리셋이 없으면 기존 `timing-keywords.ini`를 **기본** 프리셋으로 복사합니다. 기존 파일은 보존하며 이후에는 `timing-presets`의 파일을 사용합니다.
- 키워드 수는 최대 1,000개입니다. 화면 밖의 레인은 세로 스크롤 또는 Shift+휠로 이동합니다.
- 상단 확대·축소·전체 버튼은 제거했습니다. 차트의 마우스 휠로 시간 축을 확대·축소하고, 드래그/가로 스크롤로 시간을 이동합니다.
- 이벤트에 마우스를 올리면 시각(밀리초)과 원문을 볼 수 있습니다. 클릭하면 메인 로그의 해당 행을 선택합니다. 같은 픽셀에 겹친 이벤트는 확대해서 구분합니다. 같은 시각의 중복 이벤트 자체는 모두 유지합니다.

**이상 감지**는 기존과 같이 동일한 프로세스·로그 종류 안에서 같은 키워드의 연속 기록 간격을 비교합니다. **로그 간격 (ms) (0=자동)**와 **로그 간격 허용 편차 (%)**로 설정하며, 별도 연동 검사와 동시에 사용할 수 있습니다. 빨간 구간 위에 마우스를 올리면 실제 간격·기준 간격·편차를 확인하고, 클릭하면 해당 구간의 로그로 이동합니다.

기본값은 자동 기준과 ±50% 허용 편차입니다. 자동 기준은 현재 필터 결과에서 양수 간격이 5개 이상일 때 중앙값으로 계산합니다. 간격이 부족하면 자동 판정을 하지 않으며, 기준 ms를 직접 입력하면 고정 주기로 비교합니다. 같은 시각의 중복 기록은 기준 계산에서 제외하지만 기준이 있으면 0ms 간격으로 검사합니다. 비주기적 로그나 운전 정지 구간도 빨간색으로 표시될 수 있으므로 운전 주기를 나타내는 문자열과 허용 편차를 선택하세요.

```ini
[TimingKeywords]
Version="1"
Count="1"

[Keyword0]
Text="Sequence Start"
Enabled="true"
CaseSensitive="false"
Color="#08B8CC"
CheckIntervals="true"
ExpectedIntervalMs="0"
TolerancePercent="50"

[TextHighlights]
Count="1"

[Highlight0]
Text="Sequence Start"
Color="#FFFF00"
```

UTF-8 BOM INI를 사용합니다. 직접 편집할 때 따옴표 값 안의 역슬래시는 `\\`, 큰따옴표는 `\"`, 줄바꿈은 `\n`으로 표기합니다. 세미콜론과 `#`, `=` 및 한글도 값 안에서 보존합니다.

간격 검사 설정도 키워드 INI에 함께 저장합니다. 이전 INI에 새 항목이 없으면 검사 사용·자동 기준·50% 편차로 읽습니다.

문자열 강조는 `TextHighlights`와 `Highlight0`, `Highlight1` 등의 섹션에 순서대로 저장합니다. 뒤에 있는 설정이 겹치는 부분의 색상보다 우선합니다. 강조 항목이 없는 이전 INI는 강조 없음으로 읽으며, 이전 프리셋의 강조가 섞이지 않습니다. 강조는 최대 1,000개를 저장할 수 있습니다.

## 로그 형식 설정

특정 샘플의 프로세스명이나 `MAIN/COMM/TACT`에 의존하지 않습니다. **로그 형식**에서 다음 항목을 설정할 수 있습니다.

| 항목 | 사용법 |
|---|---|
| 파일 패턴 | `*.log;*.txt`처럼 세미콜론으로 구분 |
| 인코딩 | `auto`, `utf-8`, `949`, `utf-16` 또는 .NET 인코딩 이름/코드 페이지 |
| 시간 정규식 | 비워 두면 자동 인식. 사용자 규칙에는 `(?<time>...)` 그룹 사용 |
| 시간 형식 | 한 줄에 하나씩 .NET 날짜/시간 형식 입력. 비워 두면 기본 날짜/시간 형식 사용 |
| 날짜 없는 로그 기준일 | `HH:mm:ss.fff`처럼 날짜가 없는 로그에 적용 |
| 프로세스 구분 | 상대 폴더 기준 또는 파일명 정규식 기준 |
| 파일명 정규식 | 확장자를 뺀 파일명에 적용. `(?<process>...)` 필수, `(?<kind>...)` 선택 |

기본 파일명 규칙은 마지막 `_접미사`를 로그 종류로 구분합니다. 예를 들어 `Surface_AlgTask_1_MAIN.log`는 `Surface_AlgTask_1` 프로세스와 `MAIN` 종류가 됩니다. 서로 다른 폴더의 같은 파일명이 합쳐지지 않도록 상대 폴더 경로를 프로세스 이름에 포함합니다. 파일명 체계가 다르면 정규식을 수정하거나 폴더 기준을 선택합니다.

자동 시간 인식: `yyyy-MM-dd HH:mm:ss[.fraction]`, ISO의 `T` 구분, `yyyy/MM/dd`, 시간만 있는 `HH:mm:ss`, 소수점 `.`/`,`를 지원합니다. 명시된 `Z` 또는 `+09:00` 등 오프셋은 **실행 PC의 현지 시각**으로 변환합니다. 오프셋 없는 로그는 기록된 시각을 그대로 사용합니다.

예를 들어 `at=16.11.2026|12:34:56,789;msg=완료`는 다음과 같이 설정합니다.

```text
시간 정규식: at=(?<time>[^;]+)
시간 형식: dd.MM.yyyy'|'HH:mm:ss,fff
```

Unix 시각은 해당 숫자를 `time` 그룹으로 추출하고 시간 형식을 `unix-ms` 또는 `unix-s`로 입력합니다.

시간을 인식하지 못한 줄은 삭제하지 않고 **시간 미인식**으로 표시하며, 시간순 행 뒤에 파일명·원래 줄 번호 순으로 배치합니다. 차트에는 시간을 인식한 행만 표시합니다. 날짜 없는 로그의 자정 넘김은 자동 추정하지 않습니다. 여러 날짜가 섞인 시간 전용 로그는 날짜가 있는 형식으로 바꾸거나 기준일별로 나누어 읽어야 합니다.

인코딩 자동 모드는 BOM을 우선하며, BOM 없는 파일은 엄격한 UTF-8 검사 후 CP949로 시도합니다. 다른 인코딩은 명시적으로 지정하세요. 손상되거나 읽을 수 없는 파일은 부분 데이터를 정상 데이터로 섞지 않고 **읽기 경고**에 표시합니다. 빈 파일은 파일 수에 포함되며 로그 행이 없으므로 트리에 별도 행을 만들지 않습니다.

## 설정 및 데이터 보관

- `settings.ini`: 일반/다크 모드, 마지막 폴더와 프리셋, 파서 설정, 프로세스별 색상. 실행 파일 옆에 생성됩니다.
- `timing-presets/*.ini`: 프로그램별 타이밍 키워드·색상·간격 검사·강조 문자열과 색상. 폴더 전체를 복사하여 프리셋을 옮길 수 있습니다.
- `timing-keywords.ini`: 최초 기본 프리셋 생성에 사용하는 이전 형식의 파일입니다. 가져오기/내보내기도 같은 형식을 사용합니다.
- 쓰기 가능한 폴더에서 실행하세요. 원본 로그는 수정하지 않습니다.
- 파일을 불러온 시점의 데이터를 메모리에 보관합니다. 실시간 파일 감시는 없으며 추가 로그는 **불러오기**로 다시 읽습니다.
- 가상 그리드로 화면 행 생성을 줄였지만 데이터 전체를 메모리에 보관하므로 매우 큰 로그는 메모리 용량에 영향을 받습니다.
- ZIP은 먼저 압축 해제하여 폴더를 지정합니다. 제공된 샘플은 `sample-logs\2026-11-16`에 압축 해제되어 있습니다.

## 소스 빌드와 테스트

Visual Studio에서 `LogAnalyzer.sln`을 열고 Release로 빌드하거나 PowerShell에서 실행합니다. Visual Studio의 .NET 데스크톱 개발 도구와 .NET Framework 4.8 개발자 팩이 필요합니다. 외부 NuGet 패키지는 사용하지 않습니다.

```powershell
.\build.ps1
.\build.ps1 -Test
$env:LOGANALYZER_SAMPLE_ZIP = 'C:\경로\2026-11-16.zip'
.\build.ps1 -Test
.\Tests\bin\Release\Tests.exe --ui 'C:\압축해제한\로그폴더'
```

`--ui`는 이 샘플의 43,312줄을 기준으로 한 통합 테스트이며, 테스트용 설정은 Tests 출력 폴더에 생성합니다. 캡처는 `artifacts` 폴더에 생성됩니다.

검증 결과: 샘플 파일 30개(빈 파일 13개), 로그 43,312줄, `Sequence Start` 검색 326건, 기본 키워드 이벤트 847건. 형식/인코딩/INI 오류·취소·테마·검색 및 차트 원문 이동 테스트를 포함합니다.
